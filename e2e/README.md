# E2E-тесты Brand Market

Сквозные тесты. Настоящий браузер работает с настоящим API и базой. Тест сам нажимает
кнопки и заполняет формы, как пользователь.

## Что проверяется

| Файл | Сценарий |
| --- | --- |
| `auth.setup.ts` | Вход через формы: покупатель, поставщик, админ, пользователь с двумя профилями. Остальные тесты используют эти сессии. |
| `deal.e2e.ts` | Главный путь площадки. Покупатель публикует заявку, два поставщика находят её и отправляют КП (второй в «Моих КП» видит «Покупатель ещё выбирает»), покупатель выбирает первого. Победитель видит «Покупатель выбрал вас» со ссылкой на сделку, второй — «Выбран другой поставщик» и название победителя. Создаётся сделка, покупатель оплачивает её через гарантию (заглушка банка). Поставщик сдаёт работу, покупатель принимает её, деньги переводятся поставщику, покупатель оставляет отзыв. |
| `marks.e2e.ts` | Один человек, два кабинета. Знак надёжности, выданный админом, виден и в кабинете покупателя, и в кабинете поставщика. Тариф выдаётся на один кабинет: выданный кабинету покупателя, он не включён в кабинете поставщика, тот покупает свой. Значка тарифа рядом с именем нет. |
| `plans.e2e.ts` | Подписка покупателя. Без подписки заявка в ленте поставщика обычная, а покупателю показано предложение подключить тариф. После подключения заявка выделена цветом и помечена «В топе»; после отмены снова обычная. |
| `access.e2e.ts` | Гостя отправляет на вход и потом возвращает на нужную страницу. Неверный пароль не пускает. Роли не попадают в чужие кабинеты. В админку не пускает без прав. Выход завершает сеанс. |
| `team.e2e.ts` | Кто есть кто на площадке. Руководитель регистрирует компанию (нужно только название), приглашает сотрудника по почте и получает ссылку. Сотрудник регистрируется по ссылке и сразу попадает в кабинет компании как менеджер: создаёт заявку, но управлять командой не может — кнопки нет, и API отвечает отказом. Руководитель меняет доступ на «Наблюдатель» (только просмотр), потом убирает сотрудника: тот видит «У вас больше нет доступа к компании» и остаётся в личном профиле. Отдельно: фрилансер регистрируется как частное лицо, оформляет страничку (о себе, навыки, ставка, портфолио), и она открывается гостю. Демо-сотрудники из `seed.py` входят с выданным доступом. |
| `pages.e2e.ts` | Все публичные страницы и все страницы меню трёх кабинетов открываются без падения, без ошибок JavaScript и без ответов API 5xx. Переход из каталога в карточку услуги и в профиль поставщика. |
| `mobile.e2e.ts` | На экране телефона страницы не прокручиваются вбок, нижнее меню кабинета работает. |

## Запуск

Один раз установите зависимости (`npm install` или `pnpm install`) и создайте `e2e/.env` по образцу
`e2e/.env.example`. Обычно нужен только путь к Python бэкенда, `E2E_PYTHON`.

```bash
npm run e2e
```

Команда сама поднимает отдельный тестовый стенд:

- **API на :8100** с базой `<ваша_база>_e2e`. База пересоздаётся при каждом запуске и
  заполняется демо-аккаунтами из `b2b_backend/scripts/seed.py`. Платежи идут через заглушку,
  письма не отправляются, лимиты входа сняты.
- **Сайт на :4100.** Это production-сборка, как на сервере, направленная на API :8100. Сборка
  занимает 1–2 минуты.

Ваши рабочие серверы на :4000 и :8000 и рабочая база не затрагиваются. Если стенд уже запущен,
тесты переиспользуют его.

Полезные команды:

```bash
npm run e2e:ui
```
Пошаговый режим: видно браузер на каждом шаге.

```bash
npm run e2e -- e2e/deal.e2e.ts
```
Запуск одного файла.

```bash
npm run e2e:report
```
Открывает отчёт последнего запуска. Для упавшего теста в отчёте есть скриншоты и trace:
пошаговая запись с DOM и сетевыми запросами.

## Важно

- **Не запускайте тесты против рабочего сервера.** Тесты создают заявки, сделки и отзывы и
  меняют знаки демо-аккаунтов. Скрипт подготовки базы откажется работать с базой, имя которой
  не оканчивается на `_e2e`.
- На Windows используется установленный Edge, ничего скачивать не нужно. На Linux и macOS один раз
  выполните `npx playwright install chromium`.
- Тесты идут по одному: они делят общие демо-аккаунты.
